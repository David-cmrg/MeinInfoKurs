Die Aufgabe der heutigen Stunde ist die erste PHP-Seite mit Datenbankzugriff! Bis jetzt haben wir SQL immer direkt in phpMyAdmin eingetippt. Jetzt holt ein Programm die Daten und gibt sie als Webseite aus – und genau dafür gibt es PDO.

Warum PDO und nicht etwas anderes

In PHP gibt es drei Wege, auf eine MySQL-Datenbank zuzugreifen:

WegStand
mysql_*veraltet, in PHP 7 komplett entfernt – gar nicht erst anfangen
MySQLifunktioniert, aber nur für MySQL
PDOdas aktuellste Interface, funktioniert auch mit anderen Datenbanksystemen

Wenn du im Netz ein Tutorial findest, in dem mysql_query(...) steht: zuklappen und ein anderes suchen. Das ist mindestens zehn Jahre alt und läuft auf keinem aktuellen Server mehr.

Lösungsprozess der Aufgabe

ausgabe.php
/* meininfokurs.cmrg.site */ 
<?php
/**
 *
 * Eine einfache Ausgabe mit PDO
 *
 * @version 1.0 vom 16.05.2019
 * @meininfokurs.cmrg.site
 */

// Verbindung zur Datenbank aufbauen
$pdo = new PDO('mysql:host=localhost;dbname=schule', 'root', '',
       array(PDO::MYSQL_ATTR_INIT_COMMAND => "SET NAMES utf8"));

$sql = "SELECT * FROM schüler";

// Variante 1: direkt ueber query() und foreach
foreach ($pdo->query($sql) as $row) {
    echo $row['vorname']." ".$row['nachname']."<br />";
}

// Variante 2: ueber prepare() und execute()
$sth = $pdo->prepare("SELECT * FROM schüler");
$sth->execute();

echo '<br/>';
/* Alle Datensätze ausgeben */
print("Alle Datensätze ausgeben:");
echo '<br/>';
$result = $sth->fetchAll();
print_r($result);
?>

Die Verbindungszeile

$pdo = new PDO('mysql:host=localhost;dbname=schule', 'root', '',
       array(PDO::MYSQL_ATTR_INIT_COMMAND => "SET NAMES utf8"));
TeilBedeutung
mysql:host=localhostDatenbanktyp und Server – bei XAMPP läuft beides auf dem eigenen Rechner
dbname=schulewelche Datenbank
'root'Benutzername
''Passwort – bei XAMPP standardmäßig leer
SET NAMES utf8Zeichensatz, damit Umlaute nicht als Fragezeichen erscheinen

Das utf8 ist kein Luxus. Ohne das steht in der Ausgabe „Müller" statt „Müller" und der Tabellenname schüler funktioniert auch nicht. Das ist der Fehler, den bei dieser Aufgabe fast jeder einmal hat.

Benutzer root ohne Passwort ist nur in Ordnung, weil das alles lokal in XAMPP auf dem eigenen Rechner läuft. Auf einem echten Server legt man einen eigenen Benutzer an, der nur auf diese eine Datenbank darf – und gibt ihm ein Passwort.

query() und foreach

foreach ($pdo->query($sql) as $row) {
    echo $row['vorname']." ".$row['nachname']."<br />";
}

query() schickt das SQL an die Datenbank und gibt etwas zurück, das man mit foreach durchlaufen kann – genau wie eine ArrayList in Java. Jeder Durchlauf liefert eine Zeile in $row.

$row['vorname'] greift über den Spaltennamen zu. So ein Array nennt man assoziativ: der Index ist kein Zähler, sondern ein Text. In Aufgabe 5 kommt die Variante ohne das noch dran.

Der Punkt . ist in PHP das, was in Java das Plus ist: er hängt Texte aneinander. Wer aus Java kommt, schreibt hier reflexhaft ein + – das ergibt in PHP aber eine Addition und damit meistens eine 0.

prepare() und execute()

$sth = $pdo->prepare("SELECT * FROM schüler");
$sth->execute();
$result = $sth->fetchAll();

Der zweite Weg macht dasselbe in zwei Schritten: erst die Anfrage vorbereiten, dann ausführen. Das sieht umständlicher aus und ist es hier auch – sobald aber Benutzereingaben in die Abfrage kommen, ist dieser Weg der einzig richtige. Warum, kommt beim Thema SQL-Injection.

fetchAll() holt alle Zeilen auf einmal in ein Array, und print_r() gibt dieses Array mit allen Schlüsseln aus. Das ist kein hübscher Output für eine Webseite, aber unschlagbar zum Nachschauen, wie die Daten überhaupt aussehen.

Beim print_r fällt etwas auf: jeder Wert steht zweimal drin – einmal unter dem Spaltennamen und einmal unter einer Nummer. PDO liefert standardmäßig beides. Genau darauf baut Aufgabe 5 auf, die nur mit den Nummern arbeitet.

Übrigens: <br /> im echo ist HTML, kein PHP. Ein \n würde im Quelltext einen Zeilenumbruch machen, im Browser aber nichts – dort muss ein <br> stehen.
